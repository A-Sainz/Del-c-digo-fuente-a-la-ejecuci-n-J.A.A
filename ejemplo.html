Ejemplo práctico

Una suma hasta la CPU

Este ejemplo sigue un programa pequeño que calcula a + b. Cada bloque representa una etapa descrita en la guía principal.

1. Código fuente

El programador escribe variables, una operación y un valor de retorno en un lenguaje de alto nivel.

Entrada del compilador 
int main() {
    int a = 10;
    int b = 20;
    int resultado = a + b;
    return 0;
}

2. Preprocesado

Si el programa utiliza directivas como #include o #define, el preprocesador las expande antes de la compilación. En este fragmento no hay ninguna directiva, así que no se muestra una transformación concreta.

3. Compilación y ensamblado

El compilador analiza la sintaxis, comprueba reglas, puede optimizar y genera código de bajo nivel. Después, el ensamblador produce un archivo objeto con código máquina, símbolos y reubicaciones.

Representación assembly ilustrativa 
mov r0, #10
mov r1, #20
add r2, r0, r1

La salida exacta depende del compilador, las opciones y la arquitectura, por lo que este bloque representa la idea de la traducción y no una salida universal.

4. Código objeto y enlazado

El archivo objeto puede combinarse con otros módulos y bibliotecas. El enlazador resuelve las referencias externas y construye el programa enlazado.

Módulos posibles 
main.o
utilidades.o
red.o

5. Carga, memoria y ejecución

Al cargarse, el proceso utiliza zonas como .text, .data, .bss, heap y stack. Las llamadas a funciones y variables locales se relacionan generalmente con el stack; la memoria dinámica se reserva en el heap.

Resultado conceptual 
resultado = 10 + 20;
resultado = 30;

6. Observación y límites

Un depurador permitiría avanzar paso a paso e inspeccionar variables, registros, memoria y pila. Un descompilador solo reconstruiría una aproximación del código original.

Importante: este es un modelo didáctico. La representación de stack y heap, las instrucciones generadas y la disposición exacta de la memoria dependen del lenguaje, el compilador, la arquitectura y el entorno.
