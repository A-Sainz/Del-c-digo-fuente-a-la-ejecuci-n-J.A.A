Del código fuente a la ejecución

Guía didáctica con ejemplos prácticos sobre cómo un programa pasa de una idea escrita por un desarrollador a instrucciones ejecutadas por la CPU.

1. Introducción

El procesador no entiende directamente lenguajes de alto nivel. Por eso un programa recorre etapas como preprocesado, compilación, ensamblado, enlazado, carga y ejecución.

int resultado = a + b;

2. Código fuente

Es el texto escrito por el programador con variables, funciones, bucles, condicionales y estructuras de datos.

int main() {
    int a = 10;
    int b = 20;
    int resultado = a + b;
    return 0;
}

3. Preprocesador (C/C++)

Antes de compilar, el preprocesador expande directivas como #include y #define.

#include <stdio.h>
#define MAX 100

#ifdef DEBUG
    printf("Modo depuración");
#endif

4. Compilador

Analiza sintaxis, comprueba reglas, detecta errores, optimiza y genera código de bajo nivel adaptado a una arquitectura concreta (x86-64, ARM64, RISC-V...).

resultado = a + b; // puede convertirse en varias instrucciones assembly

5. Lenguaje ensamblador

Representa casi de forma directa lo que ejecuta la CPU.

mov r0, #1
mov r1, #1
add r2, r0, r1

7. Código objeto

El compilador/ensamblador produce archivos .o con código máquina, datos, símbolos y reubicaciones, por ejemplo programa.o.

8. Enlazador (linker)

Combina módulos y resuelve referencias externas:

main.o
utilidades.o
red.o

También vincula bibliotecas (por ejemplo printf).

11. Memoria de un proceso

Durante ejecución, el proceso usa zonas como .text, .data, .bss, heap y stack.

15. Heap

Zona para asignación dinámica de memoria.

int *numero = malloc(sizeof(int));
Persona persona = new Persona();

17. Stack y Heap

StackHeap
Relacionado con llamadas a funcionesMemoria dinámica
Contiene estado de ejecuciónReserva durante la ejecución
Gestión generalmente automáticaGestión dependiente del lenguaje/entorno
Estructura LIFONo funciona como pila de llamadas
Variables locales y parámetrosDatos y objetos dinámicos

La representación de crecimiento opuesto Stack/Heap es un modelo simplificado, no universal.

18. Depurador

Permite usar breakpoints, ejecución paso a paso, inspección de variables, registros, memoria y pila para detectar errores.

20. Descompilador

Reconstruye código de alto nivel aproximado desde binario:

int suma(int a, int b) {
    return a + b;
}

No recupera exactamente el original: se pierden nombres, comentarios, tipos y estructura por optimizaciones/transformaciones.

21. Análisis forense de memoria

Con herramientas como Volatility se investigan procesos, módulos, estructuras y artefactos presentes en memoria.
